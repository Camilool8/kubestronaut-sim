Local exam simulator

An exam simulator you run yourself.

A killer.sh-style rehearsal for the Kubernetes certifications, as a Docker Compose stack on your own machine: a countdown that cannot be paused, a real Linux desktop with terminals, a real two-node Kubernetes cluster to act on, and a per-check score with full solutions afterwards. Deliberately harder than the real exams.

Two banks ship today — CKAD hands-on and KCNA multiple-choice. CKA, KCSA and CKS are listed in the catalog and cannot be sat, because their banks are not written.

View the repository Documentation

Requires Docker Desktop (or docker + compose v2), python3, and about 9GB of free RAM — the XFCE desktop is inside that figure. Everything after up happens in the browser. The UI comes up before the cluster does, so the page shows the same boot progress the terminal does.

The numbers behind it

  • 119

    Questions written

    22 hands-on for CKAD and 97 multiple-choice for KCNA, counted from banks/*/exam.yaml. All original: no third-party exam dump may be committed here, because CC BY-SA 4.0 requires the banks to be ours to license.

  • 2 of 5

    Certifications with a bank

    The other three are shown in the catalog with the reason they cannot be sat, rather than as five working exams. A bank that cannot produce a meaningful score is not offered at all.

  • 0 / 100%

    The two grading gates

    A fresh environment must score 0 and the reference solutions must score 100%. tests/smoke.sh asserts both against a real stack; CI cannot run it, so it is run by hand for any change that could affect grading.

The certification track

One bank is loaded at a time, because a bank is a Kubernetes cluster seeded for its questions — so choosing another one is a destructive 2–4 minute rebuild, and the app asks first.

Three ways to run an attempt

Offered gentlest first. What each one permits is defined once in the server and enforced there, so a card cannot advertise something the server then refuses.

  • Training

    Untimed. Two-tier hints and solutions on demand, and scoring that does not end the attempt. This is how the product meets WCAG 2.2.1 Timing Adjustable — the unpausable countdown stays the default, but it is opted into rather than imposed.

  • Mastery

    Half the bank's duration and no help: 60 minutes for CKAD, 45 for KCNA. For a candidate who already knows the material and wants the clock to hurt.

  • Exam

    The bank's full duration and no help. The timer is server-side, not in the tab, and it cannot be paused. At zero the exam ends and grading starts by itself.

What this is not

Stated rather than implied, because the alternative is letting a reader infer something the software does not do.

No accounts, and no authentication anywhere.
Permanently. This is a local single-user tool and a password field would be theatre; the only real control is which interface it binds to. Ports bind to all interfaces by default, so on a network you do not control, start it with SIM_BIND=127.0.0.1 ./sim up.
No hosted version.
There is nothing to sign up for and nothing is uploaded. Local single-user is the permanent model, not a stage before a service, so hosting, accounts and multi-user separation are out of scope rather than unbuilt.
No adoption numbers, testimonials, or pass-rate claims.
There are none to report. A score here measures practice progress; it does not predict a real exam result.
No attempt history.
One session at a time, and one attempt record overwritten per attempt. There is no cross-attempt analytics and nothing here promises progress over time.
No third-party exam dumps.
Every question is original. The banks are CC BY-SA 4.0, which requires them to be ours to license, so a dump could never be committed here.
No hands-on exam on a phone.
The desktop requirement is functional, not a styling shortcut: the answer surface is a real remote desktop. Small screens get an explanation instead of a broken layout. A KCNA attempt does work on a phone, because the multiple-choice engine never touches the cluster.

Why the score means something

Hands-on questions are graded on behaviour wherever behaviour is the point — a policy that actually denies, an Ingress the controller really routes — not on the shape of your YAML. That is only possible because the environment is complete enough to test an answer the way the real exam expects.

  • Calico, not kindnet

    NetworkPolicies are genuinely enforced, so a policy question can be graded on whether traffic is actually denied.

  • ingress-nginx

    An Ingress question has a controller behind it, so the route either resolves or it does not.

  • A local Helm repository and registry

    Plain HTTP, on the cluster network, so the image-building and packaging half of the curriculum is answerable offline.

  • Weights the build checks

    A domain's share of an exam's points is its published curriculum weight, and tests/bank-weights.sh fails the build if any domain drifts more than two percentage points from it.
